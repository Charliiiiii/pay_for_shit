# 微信小程序从 0 到 1 实战沉淀（本项目版）

本文基于 `pay_for_shit_frontend` + 云开发后端的完整落地过程，沉淀一份可复用的方法论。

## 1. 项目目标与边界

- 目标：做一个可上线的小程序 MVP，覆盖计时、设置、历史、日历、排行榜、分享图。
- 技术约束：优先微信原生小程序，减少额外构建链路。
- 后端策略演进：
  1. 本地 Node.js/Express 原型验证接口模型；
  2. 切换至微信云开发（云函数 + 云数据库）做真实可用版本。

## 2. 架构演进路径（踩坑后确认）

### 阶段 A：本地优先，快速验证业务

- 前端先走 `wx.setStorageSync`，确保核心交互和计算逻辑闭环。
- 后端先有一版可跑 API，验证数据模型是否合理（用户设置、记录、排行榜）。
- 收益：可以快速完成产品形态，不被云权限和环境配置卡住。

### 阶段 B：云化改造，进入可分享状态

- 接入 `wx.cloud.init` + 统一云函数入口 `api`。
- 把核心读写迁移到云函数：
  - `settings.get/put`
  - `records.list/batchUpsert/clear`
  - `leaderboard.week`
- 前端保留本地兜底，云失败时不阻塞主流程。

## 3. 数据建模与索引（关键经验）

集合：

- `settings`：用户设置（每用户 1 条）
- `records`：计时记录（多条）
- `profiles`：用户昵称

索引建议：

- `settings`：`_openid` 唯一
- `profiles`：`_openid` 唯一
- `records`：
  - `(_openid, endTime)` 非唯一（个人列表）
  - `(_openid, clientId)` 唯一（幂等去重）
  - `endTime` 非唯一（全站周榜按时间范围聚合时避免超时）

经验：

- `_id_` 是系统默认索引，不要删。
- 少一个关键索引，云函数超时概率会显著增加。

## 4. 云函数设计原则

### 4.1 统一入口 + action 分发

- 一个 `api` 云函数通过 `event.action` 分派，利于小项目快速迭代。
- 统一返回结构：
  - 成功：`{ ok: true, data }`
  - 失败：`{ ok: false, message }`

### 4.2 幂等与批量

- 上报记录使用 `clientId` 唯一键，保证重复提交不重复入库。
- 批量上报时先批量查重再分批写入，避免串行请求放大时延。

### 4.3 排行榜避免“全量拉取后内存聚合”

- 初版全量 `get()` + JS 聚合，数据量上来后容易 timeout。
- 改为数据库端 `aggregate().group().sort().limit()`。

## 5. 前端云化改造经验

### 5.1 先“可用”再“完美”

- 设置保存：本地先写，再云同步。
- 计时结束：本地先入记录，再异步上云。
- 核心原则：用户操作有即时反馈，云层作为增强而非阻塞。

### 5.2 拉取与回填

- 只“上云不下云”会导致换设备数据断裂。
- 首页/历史/日历进入时增加云端下拉同步，并回填到本地缓存。

### 5.3 配置项沉淀到 settings

- 例如“排行榜是否显示金额”这种 UI 策略，放入 settings 统一管理，便于后续扩展。

## 6. 最常见问题与排查清单

### 6.1 `Error: timeout`

优先排查：

1. 云函数是否已部署到最新代码；
2. 关键索引是否齐全；
3. 是否存在全量扫描 + 应用层聚合；
4. 云函数日志里哪个 action 超时。

### 6.2 `请在 cloudfunctionRoot 选择云环境`

- 在开发者工具中绑定 `cloudfunctions` 根目录对应 env。
- 确认 `project.config.json` 包含：
  - `"cloudfunctionRoot": "cloudfunctions"`

### 6.3 排行榜时长全是 0

- 大概率是云函数仍是旧版，未返回 `durationSeconds/durationText`。
- 重新部署云函数并检查 records 是否有 `durationSeconds` 字段。

## 7. 视觉系统经验（粉白低饱和）

- 用一套主色映射全局替换，避免页面色彩割裂。
- 降低饱和度优先做这几类：
  - 主按钮色
  - 主文字色
  - 边框/分隔线
  - 背景底色
- 动效方面，计时页尽量避免 `scale` 呼吸动画与数字更新叠加，容易造成“抖动感”。

## 8. 发布前检查（最小可上线）

1. 云函数部署：`api` 最新；
2. 集合索引：全部 ready；
3. 真机关键路径：
   - 设置保存
   - 计时上报
   - 历史/日历同步
   - 周榜展示
4. 异常回退：
   - 云失败时本地可用
   - 提示文案不误导。

## 9. 下一步可持续优化

- 好友榜从占位改为真实关系链（`friend_links` 集合 + `leaderboard.friends`）。
- 增加“云同步状态”与日志埋点，便于定位线上问题。
- 抽离主题 token（颜色、圆角、阴影）统一维护，降低后续 UI 调整成本。
